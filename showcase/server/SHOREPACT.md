Shorepact runs a browser playtest at /shorepact/play/. Native, browser and configured Discord clients share the same eight-character rooms and Quick Match queue. The original hex game is the currently supported title. Clients host the rules; the relay never writes games or room codes to disk. A host leaving ends the game. The broker is bounded to 512 open connections. Game Center is a distinct service.

The commercial client distribution in data/shorepact.pack (including artwork and the compiled rules) is © its respective owners and is excluded from the repository's MIT license. Third-party notices travel in the client. To produce the pack from a vetted WebBundle use tools/deploy/pack-shorepact.mjs with the release key in SHOREPACT_SITE_KEY. The binary is authenticated and encrypted; do not commit the key or any invitation. Fly's existing app supplies the key at runtime. Missing keys fail closed for the browser. The access gate uses a short-lived HttpOnly cookie; do not enable SHOREPACT_PUBLIC_PLAY without the publisher's distribution decision. Shorepact native origins can connect without a browser cookie. Those origin checks are a browser cross-site control, not proof of purchase.

In fly.toml SHOREPACT_ROOM_MACHINE is the coordinator for all sockets, including those which initially reach the other machine. When replacing the coordinator, update that setting; a restart ends live tables. On rollout check direct and replayed handshakes and a complete game move. For Discord set SHOREPACT_DISCORD_APP_ID to the assigned public application ID and configure the root Activity URL mapping to the production host's shorepact/play path. No OAuth tokens are needed for the current room-code feature. Verify invitation entry, SDK ready and the socket with an actual Discord launch before claiming availability.
