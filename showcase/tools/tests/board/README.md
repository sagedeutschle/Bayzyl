# Board ports and native fixture provenance

`board-games-check.mjs` checks six browser engines against `native-fixtures.json`, emitted by compiling `native-fixtures.swift` alongside the unchanged Prismet Foundation models. The native application, projects, accounts and saves are not touched. Source inputs are iOS `Core/Games/{Game2048,ConnectFourGame,ConnectFourAI,ReversiGame,ReversiAI,GomokuGame,GomokuAI,CheckersGame,CheckersAI,SeaBattleGame,SeaBattleAI}.swift` and macOS `Model/{ChessTypes,Position,MoveGenerator}.swift`. Compile with `swiftc <those files> native-fixtures.swift -o <temporary executable>` and capture stdout to the fixture. Source hashes accompany the fixture.

All engines export default `initial(seedUInt64String, options)`, immutable `apply(state, action)`, `status`, `validate`, `view`. Outcome is from the first player's perspective: red/black/dark/host/White. `view` supplies the complete grid, accessible labels, selectable/legal cells and controls. Settings use `mode: local | bot` and `difficulty: easy | normal | hard`. Bot moves are explicit `type: bot` controls; the shell may schedule these for the second player when mode is bot. Do not silently move a player's first turn.

Rules are native ports. All search bots share a deterministic 8,000-node maximum across the whole root move search, as well as depth limits. Browser adapters use lower-case player names, flattened coordinates and JSON-safe arrays. Native ELO is not claimed: search is bounded (Connect Four 1/3/4 plies, Reversi 1/3/4, Gomoku 1/2/3, Checkers 1/2/4, Chess 2/3/3). Chess uses exact native material/PST tables but seeded rather than nondeterministic selection from its difficulty pool; its repetition identity ignores an uncapturable en-passant target. Chess additionally refuses missing-rook castling and king captures when validating imported positions. Sea Battle starts with the native seeded predeployed fleets; custom deployment is not exposed in this adapter. Its target projection hides all unhit enemy ships. Local two-player saves are plaintext and are not an adversarial hidden-information protocol.

Native file/cloud transfer still covers its separately defined three-game schema; these browser states must not be passed to that validator as if they were already supported. No browser UI or live multiplayer acceptance is established by engine tests.
